# Мини-учёт оплат учебного центра

REST API для учеников и оплат, отчёт «должники за месяц» и мобильная веб-страница (вариант Б): список должников и форма добавления оплаты.

**Стек:** Node.js + TypeScript, Fastify, SQLite (`better-sqlite3`), валидация — zod, тесты — vitest. Фронтенд — один HTML-файл без сборки.

## Запуск с нуля

Нужен **Node.js 20+** и npm.

```bash
git clone <repo-url> ecomdev-payments
cd ecomdev-payments
npm install
npm run seed   # необязательно: 6 демо-учеников с оплатами за текущий месяц
npm run dev    # http://localhost:3000
```

Откройте <http://localhost:3000> — страница должников (удобнее всего с телефона или в режиме мобильного устройства в DevTools).
Чтобы открыть с телефона в той же Wi-Fi сети: `http://<IP компьютера>:3000`.

Другие команды:

```bash
npm test                 # 34 теста: API учеников, оплат и расчёт должников
npm run build && npm start   # production-сборка (dist/)
```

Настройки через переменные окружения (см. `.env.example`):

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PORT` | `3000` | порт HTTP-сервера |
| `DB_PATH` | `data/app.db` | путь к файлу SQLite (создаётся автоматически) |
| `TZ` | `Asia/Tashkent` | часовой пояс для «сегодня» и «текущего месяца» |

### Через Docker (если не хочется ставить Node)

```bash
docker build -t ecomdev-payments .
docker run -d --name payments -p 3000:3000 -v payments-data:/app/data ecomdev-payments
docker exec payments node dist/scripts/seed.js   # демо-данные, необязательно
```

## API

Все суммы — целые числа в сумах. Даты — `YYYY-MM-DD`, месяц — `YYYY-MM`.
Ошибки валидации → `400 { "error": "...", "details": [{ "path", "message" }] }`, не найдено → `404`.

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/students` | создать ученика `{ name, phone, group, monthlyFee }` → `201` |
| `GET` | `/students?group=` | список учеников (фильтр по группе необязателен) |
| `GET` | `/students/:id` | один ученик |
| `PATCH` | `/students/:id` | изменить любые поля |
| `DELETE` | `/students/:id` | удалить (мягкое удаление, история оплат сохраняется) → `204` |
| `POST` | `/students/:id/payments` | добавить оплату `{ amount, date? }` (дата по умолчанию — сегодня) → `201` |
| `GET` | `/students/:id/payments` | оплаты ученика, новые первыми |
| `GET` | `/debtors?month=YYYY-MM` | должники за месяц (без `month` — текущий месяц) |

Примеры:

```bash
curl -X POST localhost:3000/students -H 'content-type: application/json' \
  -d '{"name":"Али Валиев","phone":"+998901234567","group":"IELTS-1","monthlyFee":500000}'

curl -X POST localhost:3000/students/1/payments -H 'content-type: application/json' \
  -d '{"amount":200000,"date":"2026-10-03"}'

curl 'localhost:3000/debtors?month=2026-10'
# {"month":"2026-10","total":300000,"debtors":[{"id":1,"name":"Али Валиев","phone":"+998901234567",
#   "group":"IELTS-1","monthlyFee":500000,"paid":200000,"debt":300000}]}
```

### Как считается долг

Для месяца `M`:

```
оплачено(M) = сумма оплат ученика с датой внутри календарного месяца M
долг(M)     = monthlyFee − оплачено(M)
должник     ⇔ долг(M) > 0
```

- Учитываются только неудалённые ученики, добавленные не позже последнего дня месяца `M` (за месяцы до появления ученика долга нет).
- Ученик, добавленный в середине месяца, должен полную сумму за этот месяц (без пропорционального расчёта).
- Переплата **не переносится** на другие месяцы; оплата 30 сентября не закрывает октябрь.
- Используется текущая `monthlyFee` ученика (истории изменения цены нет).
- Сортировка: по долгу по убыванию, затем по имени. `total` — сумма всех долгов.

Эти упрощения сознательные — см. «Что бы я улучшил».

### Структура

```
src/
  app.ts        сборка Fastify-приложения (используется сервером и тестами)
  server.ts     точка входа
  db.ts         подключение SQLite и схема
  dates.ts      работа с датами/месяцами в TZ сервера

  students.ts   репозиторий + маршруты учеников

  debtors.ts    SQL-запрос и маршрут должников
public/index.html   мобильная страница
scripts/seed.ts     демо-данные
test/               тесты API (in-memory SQLite)
openspec/           спецификация, дизайн и план задач (OpenSpec)
```

## Что бы я улучшил, будь ещё неделя

1. **Баланс вместо помесячного расчёта.** Переплата переносится на следующие месяцы, долг накапливается за прошлые месяцы. Плюс история цен (`monthlyFee` с датой начала действия), чтобы смена цены не меняла прошлые отчёты.
2. **Авторизация и роли.** Сейчас API и страница открыты всем, у кого есть URL. Нужен вход для администраторов и журнал «кто внёс оплату».
3. **Редактирование и отмена оплат.** Ошибочно внесённую оплату сейчас не исправить через API. Нужна отмена (сторно) с сохранением истории, а не удаление.
4. **Telegram-бот поверх того же API.** `/debt`, `/pay <id> <сумма>` и автоматические напоминания должникам. Плюс экспорт отчёта в Excel.
5. **Production-готовность.** PostgreSQL и миграции вместо `CREATE TABLE IF NOT EXISTS`, пагинация списков, OpenAPI/Swagger-документация, CI с тестами и линтером.
